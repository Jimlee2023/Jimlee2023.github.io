## 1. 개발팀 (시니어 프런트엔드)

**[치명] D1. 목록에서 조회수에 쉼표를 넣으면 기존 값이 조용히 지워짐** — 721행 `num()`, 809~815행 `change` 처리
네이버 통계의 "1,234"를 `type="number"` 칸에 붙여넣으면 브라우저가 `value=''`로 줘서 `null`로 저장되고, 화면에는 "저장했어요"가 뜸.
수정: `<input type="text" inputmode="numeric" ...>`로 바꾸고 읽을 때 숫자만 남기기:
```js
const raw = t.value.replace(/[^\d]/g,''); const v = raw === '' ? null : parseInt(raw,10);
```
수정 창의 `f-views/likes/comments`(355~357행)와 `readDlg`에도 똑같이 적용하기. 지금은 브라우저 자체 오류 풍선이 떠서 초보자가 이해하기 어려움.

**[치명] D2. 발행 주소 칸(`type="url"`, 353행)에 `https://`를 빼고 넣으면 저장이 막힘**
`blog.naver.com/hjw1997/…`나 `m.blog.naver.com/…`처럼 붙여넣으면 폼 검사에 걸려서 영어/브라우저 메시지만 보임. "발행했어요" 흐름(커서가 이 칸으로 감)에서 가장 자주 생김.
수정: `type="text"`로 바꾸고 `readDlg`에서 `if (o.url && !/^https?:\/\//i.test(o.url)) o.url = 'https://' + o.url;` 추가. 주소가 http/https가 아니면 저장하지 않기(`javascript:` 차단용).

**[치명] D3. 휴대폰(700px 이하)에서 달력 날짜를 누르면 글이 열리지 않고 "새 글 추가"가 열림** — 200행 CSS
글 칩이 높이 8px 막대로 줄어서 칩을 정확히 누르기 어렵고, 나머지 영역(`.day[data-add]`)을 누르면 새 글 추가 창이 뜸. 그대로 두면 중복 글이 생김.
수정: 클릭 처리(789행)에서 `data-add` 칸에 글이 있으면 첫 번째 글 열기(또는 해당 날짜로 목록 필터). 새 글 추가는 빈 날짜일 때만.
```js
else if (t.dataset.add){ const dp = allPosts().filter(p=>p.iso===t.dataset.add); dp.length ? openDlg(dp[0].id) : openDlg(null,{addIso:t.dataset.add}); }
```

**[중요] D4. 모달이 열린 상태에서 복사 대체 경로가 실패해도 "복사했어요"가 뜸** — 748~752행
`<dialog>`가 열려 있으면 body에 붙인 textarea는 선택할 수 없는 상태(inert)라 실패함. 또 `execCommand`는 실패하면 예외 대신 `false`를 돌려주는데, 코드는 예외만 잡고 있음. file://가 Chrome에서는 보안 컨텍스트라 보통은 `navigator.clipboard`로 가지만, 삼성 인터넷이나 구형 브라우저에서 이 문제가 드러남.
수정: `const host = $('dlg').open ? $('dlg') : document.body; host.appendChild(ta); ... if (!document.execCommand('copy')) throw 0;`

**[중요] D5. 창을 켜둔 채 자정이 지나면 날짜가 안 바뀜** — 496행 `const TODAY`
다음 날 체크리스트가 어제 날짜로 저장되고, 밀림 판정도 하루 늦어짐.
수정: `document.addEventListener('visibilitychange', () => { if (!document.hidden && isoOf(new Date()) !== TODAY) location.reload(); });`

**[중요] D6. 예전 데이터를 가져올 때 상태값을 검사하지 않음** — 529행 `migrateOld`
예전 캘린더의 status가 `done` 같은 다른 이름이면 배지에 "undefined"가 뜨고 선택 상자가 비어 보임.
수정: `if (f==='status' && !['scheduled','draft_ready','published'].includes(o[f])) return;`. 같은 이유로 `cat`도 CAT_NAME에 있는 값만 받기.

**[중요] D7. 백업 불러오기 검사가 약함** — 879~885행
`custom:null`처럼 잘못된 파일이면 `allPosts()`에서 오류가 나서 화면이 멈춤. 불러오기 확인 창에서 취소를 누르면 `e.target.value=''`까지 가지 않아서 같은 파일을 다시 고를 수 없음.
수정: `Array.isArray(s.custom) && typeof s.edits==='object'`를 검사하고, `e.target.value=''`는 `finally`로 옮기기.

**[중요] D8. ICS 알림(`TRIGGER:PT9H`)은 기기마다 다르게 동작함**
- iPhone/맥 캘린더: 당일 09:00 알림 동작
- **구글 캘린더 가져오기는 VALARM을 무시함** → 해당 캘린더의 기본 알림만 적용됨
- 네이버 캘린더와 일부 안드로이드 캘린더는 양수 트리거(시작 후 N시간)를 무시할 수 있음

지금 문구("그날 아침 알림을 받을 수 있어요")는 정직성 목표와 어긋남. 문구를 "아이폰은 자동 알림, 구글은 캘린더 기본 알림 설정 필요"로 바꾸기. 발행한 뒤 다시 받아도 이미 넣은 일정은 지워지지 않는다는 안내도 추가.
그 밖의 ICS 형식(DTSTAMP, UID, VALUE=DATE 종일 일정, 이스케이프, 줄 접기)은 적합함. `METHOD:PUBLISH`는 넣으면 좋음([사소]).

**[사소] D9.** CSV(893행)는 BOM + UTF-8이라 엑셀에서 한글이 정상으로 보임. 다만 제목이 `=`, `+`, `-`, `@`로 시작하면 수식으로 해석되니 앞에 `'`를 붙이기. 줄바꿈은 `\r\n` 권장.
**[사소] D10.** 수정 창 안에서 띄운 알림(toast, z-index 99)은 top-layer인 dialog의 backdrop 뒤에 가려져 흐리게 보임. 창이 열려 있으면 dialog 안에 알림을 띄우기.
**[사소] D11.** 좁은 화면에서는 칩의 `font-size:0` 때문에 🛒 표시도 사라짐. 쇼핑 글은 칩 색이나 테두리로 구분하기.
**[사소] D12.** 목록에서 상태를 '발행 완료'로 바꿨는데 주소가 이미 있으면(809행) 오늘 체크리스트의 '발행'이 자동으로 체크되지 않음. 수정 창에서 저장할 때와 동작이 다름.
**[사소] D13.** 휴대폰 Chrome은 file:// 파일을 열기 어렵고, PC와 저장소가 따로임. 백업과 불러오기로 옮겨야 한다는 안내를 휴대폰 화면에 보여주기. 마지막 백업 날짜를 기록하고 "7일 넘음" 경고를 띄우면 더 좋음.
**[사소] D14.** 외부 폰트(CDN)는 오프라인이면 맑은 고딕으로 대체되니 문제없음.

## 2. 전략팀 (C-Rank/SEO)

**[치명] S1. 현재 10월 계획이 규칙 ①을 스스로 어기고 있음**
10/15~31 쇼핑 글은 10/17, 10/22, 10/27, 10/30으로 4편이고, 27→30 간격이 3일임. 10/31로 옮겨도 4일이라 여전히 위반.
17일부터 시작하면 5일 간격으로 3편만 들어감. 4편을 넣으려면 **10/15·20·25·30**으로 재배치해야 함. 아니면 10/30 글의 링크를 빼고 11월로 넘기기.
추가로 간격 위반은 명시된 규칙 위반인데 경고가 🟠 주황이라 약함. 🔴 빨강으로 올리기.

**[중요] S2. 규칙이 10/31에서 끝남** — 507~510행
11월부터는 쇼핑링크가 몇 편이든 "문제없어요"로 나옴. 규칙 ①의 "한 달 최대 4편"을 10/15 이후 **매달**, **달 경계를 넘는 간격 검사**(예: 10/30 → 11/2)까지 포함하도록 일반화하기.
```js
{ from:'2026-10-15', to:'9999-12-31', perMonth:4, minGap:5 }
```

**[중요] S3. 하루 1편 검사가 발행한 글을 빼고 셈** — 612행
오늘 1편을 발행하고 같은 날 1편을 더 예정해도 경고가 없음.
수정: `p.iso >= TODAY` 조건만 두고(상태 무관) 모두 세기. 1편 이상이 미발행일 때 경고하기.

**[중요] S4. 비슷한 키워드를 못 잡음**
공백과 기호만 없앤 뒤 완전히 같은지만 비교해서 다음과 같은 겹침을 놓침:
- 「복막투석 외식」(8/18) ↔ 「투석 외식」(9/19)
- 「크레아티닌 정상수치」 ↔ 「크레아티닌 수치」
- 「복막투석 단백질」(10/9) ↔ 「복막투석 두부 단백질」(10/3)
- 「복막투석 추석」 ↔ 「복막투석 추석 일상」

수정: 한 키워드가 다른 키워드를 포함하거나, 두 키워드의 단어가 전부 겹치면 🟠(주의)로 표시.

**[중요] S5. 밀린 12편 중 시즌 글은 날짜만 옮기면 안 됨**
2026년 추석(9/25) 관련 글인 9/21 독감 "오늘 시작"(당일 발행 필수), 9/23·24·25, 9/26·27 명절 후 글은 이미 시기가 지남. 밀림 경고에 **분야=시즌이거나 메모에 '당일'이 있는 글은 "보류/삭제 권장"**으로 따로 표시하기. 그대로 10월로 밀면 시기 안 맞는 글이 C-Rank 신뢰도를 떨어뜨림.

**[중요] S6. 조회수를 언제 쟀는지 기록이 없음**
누적 조회수라 D+1에 적은 글과 D+30에 적은 글을 비교할 수 없음. `viewsAt`(측정일)을 저장하거나 기록 시점을 "발행 7일 후"로 통일하기. 규칙 ④ 문구("발행 다음 날")와 체크리스트("어제 글")도 같은 기준으로 맞추기.

**[사소] S7.** 중복 검사가 "둘 다 이미 발행된 글"은 건너뜀. 예: 「인 수치」(8/20, 9/14), 「회고」. 과거 기록이라 괜찮지만, 이 키워드로 새 글을 쓸 때 참고하도록 표시해주면 좋음.

## 3. 블로그 관리팀 (일일 운영)

**[치명] M1. 밀린 글을 옮길 빈 날이 없음**
10/1~10/31이 하루 1편으로 꽉 차 있어서, 밀린 12편 중 하나를 옮길 때마다 "하루 2편" 경고가 새로 뜸. 초보자는 어떻게 해야 할지 막힘.
해결: 밀림 경고에 **[다음 빈 날로 옮기기]**(현재는 11/1부터 비어 있음)와 **[이후 일정 하루씩 뒤로 밀기]** 버튼 추가. S5의 시즌 글은 [보류] 버튼으로 처리.

**[중요] M2. 첫 화면 경고가 너무 많음**
빨강 2개, 주황 3개, 파랑 2개에 조회수 미입력 48편까지 겹침. 파랑 경고는 기본으로 접어두고, 조회수 미입력은 "최근 14일"만 경고하고 나머지는 목록 필터로 보내기.

**[중요] M3. 체크리스트 '쇼핑링크 규칙 확인'은 사람이 직접 체크해야 함**
자동 점검이 이미 알고 있는 내용이니 오늘 글이 규칙을 지키면 자동으로 체크하고, 어기면 빨간 문구를 보여주기. '발행'과 '주소' 체크처럼 앱이 판단할 수 있는 항목은 자동으로 맞추기.

**[중요] M4. "날짜 옮기기" 버튼 이름**
누르면 수정 창 전체가 열리고 날짜 칸으로 바로 가지 않음. 날짜 칸에 커서를 두거나 버튼 이름을 "수정"으로 바꾸기.

**[사소] M5.** 목록 필터('아직 안 쓴 글', '쇼핑링크')는 현재 달만 보여주는데 버튼만 봐서는 알 수 없음. 버튼 이름에 "(이 달)"을 붙이기.
**[사소] M6.** 공감·댓글 칸이 발행 전에는 비활성(회색)인데 이유 설명이 없음. "발행 후 입력" 같은 안내(title) 추가.
**[사소] M7.** [처음 상태로] 버튼이 인쇄 버튼 옆에 있어 잘못 누르기 쉬움. 맨 아래로 떼어놓기.
